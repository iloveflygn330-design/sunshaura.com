# きょうりゅうラン ランキングの設定手順

ミニゲーム「きょうりゅうラン」のランキングを、Google スプレッドシートに保存するための設定です。
最初に1回だけ行います。このフォルダ（`tools/`）はサイトには公開されません。

設定するまでは、ランキングは「このブラウザだけの仮ランキング」になります（テスト用）。

## 1. スプレッドシートを作る

1. Google ドライブで、新しいスプレッドシートを作る（名前は自由。例：`きょうりゅうラン ランキング`）
2. メニューの **拡張機能 → Apps Script** を開く
3. 最初から入っているコードを全部消して、このフォルダの `Code.gs` の中身をまるごと貼り付ける
4. 上の **保存**（フロッピーのアイコン）を押す

## 2. タイムゾーンと Discord の設定

1. Apps Script の左のメニューの **⚙ プロジェクトの設定** を開く
2. **タイムゾーン** を「(GMT+09:00) 日本標準時 - 東京」にする（月間ランキングの区切りに使う）
3. 下の **スクリプト プロパティ** で「スクリプト プロパティを追加」を押して、次を入れる

| プロパティ | 値 |
|---|---|
| `DISCORD_WEBHOOK_URL` | 全期間1位が入れ替わったときに通知する Discord の Webhook URL |
| `GAME_URL`（任意） | 通知に付けるリンク。書かなければ `https://sunshaura.com/minigame/?game=dinorun` |

- Webhook URL は秘密の値なので、コードやサイトのファイルには書かないでください（ここに入れるだけ）。
- GitHub の Secrets に入れた値は、あとから見ることができません。
  Discord の「サーバー設定 → 連携サービス → ウェブフック」で、使いたいウェブフックの **ウェブフックURLをコピー** を押してコピーしてください（ニュースと同じチャンネルでよければ、同じウェブフックで大丈夫です）。
- 通知がいらないときは、`DISCORD_WEBHOOK_URL` を入れなければ通知されません。

## 3. ウェブアプリとして公開する

1. 右上の **デプロイ → 新しいデプロイ** を押す
2. 「種類の選択」の ⚙ から **ウェブアプリ** を選ぶ
3. 次のように設定して **デプロイ** を押す
   - 説明：自由（例：`ランキング v1`）
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「アクセスを承認」を求められたら、自分の Google アカウントを選んで許可する
   （「このアプリは Google で確認されていません」と出たら、**詳細 → （プロジェクト名）に移動** で進む。自分で作ったものなので大丈夫です）
5. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピーする

## 4. サイト側に URL を書く

`minigame/assets/dinorun-config.js` の `rankingUrl` に、コピーした URL を貼る。

```js
rankingUrl: 'https://script.google.com/macros/s/……/exec',
```

この URL は公開されても大丈夫です（書き込みのチェックは Apps Script 側でしています）。

## 5. 動作確認

- ブラウザで `（URL）?action=top` を開いて、`{"ok":true,"all":[],"month":[]}` のように出れば成功
- ゲームを遊んで名前を登録すると、スプレッドシートに `scores` というシートができて、1行増える
- Discord 通知の確認：Apps Script の画面で関数 `testDiscord` を選んで **実行** すると、テストの通知が届く

## こんなときは

- **変なスコアを消したい** … スプレッドシートの `scores` シートで、その行を削除するだけ
- **Code.gs を書き換えたとき** … **デプロイ → デプロイを管理** → ✏（編集）→ バージョンを「新バージョン」にして **デプロイ**
  （「新しいデプロイ」にすると URL が変わってしまうので注意）
- **スコアの計算・最高速・名前のルールを変えたとき** … `Code.gs` の上の設定と、`dinorun-config.js` の値を同じにする
  （合っていないと、正しいスコアも「score check」などで弾かれる）

## 不正対策（Code.gs がしていること）

ゲームはブラウザの中で動いているので、完全には防げません。そのかわり、次のような「ありえない記録」は登録しません。

- ゲーム開始時に発行した受付番号がないスコア（遊ばずに送ったもの）。受付番号は1回だけ使える
- 受付からの経過時間より、遊んだ時間が長いもの
- 最高速でも走れない距離
- 距離に対して、コインや壊した数・かすりの回数が多すぎるもの
- 距離・コイン・壊した数・かすりの回数から計算したスコアと合わないもの
